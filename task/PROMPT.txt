为合成构建清单编写只读安全审计，检查哪些开关组合会把敏感来源带进发布目标。输入为最多 24 个布尔开关、开关合法组合约束、配置 DAG 和若干最终可发布目标。节点区分公共来源、敏感来源、合并和经批准的清理步骤；每条有向边带布尔条件。配置给出清理步骤在何种条件下可将哪些敏感类别移除。对同一个开关赋值，所有成立的入边都贡献来源风险；风险按类别取并集，清理只影响通过该节点的类别，同类别的另一条绕行路径仍有贡献。每个发布目标给允许敏感类别；发现含禁用类别时拒绝。
find 输出每个不安全目标的字典序最小合法开关赋值（开关 ID 升序、false 先于 true），按目标、类别 ID 排序，并给长度最短、同长按边 ID 序列最小的未清理来源链。compare 在两份同开关集的清单间找每个目标新增和消失的泄露类别及最小变化赋值；比较只限两边共同合法赋值。没有共同合法赋值须明确报告。构建约束、边条件和清理条件可用 AND、OR、NOT 与开关引用，需严格解析，不运行真实构建。支持 200 节点、500 边，说明符号化求值或剪枝。测试覆盖清理链被绕过、不同开关赋值形成不同危险路径、旧新合法域不一、同名目标不存在与独立小模型核对。

增加 remediate，找一组固定的获批变更，使在所有合法开关组合下没有禁用类别流入任何发布目标，且输入列为必备的公共来源仍可到达对应目标。候选动作或者禁用一条边的指定条件子集，或者扩充某节点在指定条件下清理的类别；同一边或节点上的互斥候选不能并选。每种公共来源只在自己的需求公式为真时要求到达，清理步骤不能代替对实际输入消失的检查。最小化总变更成本、变更数量和升序动作 ID，返回最终全量安全审计与每个必要可达条件的成立见证摘要；无解给最小未满足的需求实例及其布尔赋值。不得以分别对每个赋值选择一套动作代替全局固定策略。支持 18 个备选动作，需共享判定状态并解释剪枝。测试至少覆盖关闭泄露边会连带阻断必须公共来源、少量低成本动作组合同时生效才修正绕行、只对单一赋值安全却不能全体发布、多个目标互相牵制、并列决胜和小开关域穷举对照。

项目从空仓库起步，验收环境为 Windows 原生 Python 3.12，仅用标准库和 CPU；构建清单与测试夹具均采用本地虚构数据。用 `python -m solution <命令> CASE.json` 跑审计，有持久状态的命令还要带 `--db DB.sqlite`。检查结果输出到 stdout，编码为 UTF-8、格式为 JSON，并对相同逻辑输入保持一致。结构错误须给错误码和字段位置。请附可直接运行的配置样例，README 说明完整的输入输出及复现命令，断言测试统一以 `python -m unittest discover -s tests -v` 执行。
